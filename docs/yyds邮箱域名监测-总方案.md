> 仓库名：`domainslot`  
> 界面名：**yyds邮箱域名监测**

## 1. 总方案名与项目定位

| 项 | 值 |
| --- | --- |
| 总方案名 | yyds邮箱域名监测 |
| 仓库 / 目录名 | `domainslot` |
| 本地路径 | `C:\Users\Administrator\codex-1\domainslot` |

## 2. 已确认边界

1. 这是新项目，不是 gptimage2api 的功能。
2. 不考虑 Cloudflare Temp Email。
3. 不猜测、不探测 OpenAI 是否拉黑域名。拉黑由人看注册情况后，在本监控或 yyds 官网删。
4. **已绑定的域名可以从本监控删除 yyds 侧记录。** 调用 `DELETE /me/domains/{id}`，并只清理阿里云上对应的邮箱解析（验证 TXT、根域 MX、通配 MX，以及补位时会清掉的 `@`/`*` 冲突 A/CNAME）。不删 NS、SOA、`www` 和其他无关记录，也不整域清空。补位中的域名不能删。未绑定域名默认不能删；若上次已从 yyds 删掉但阿里云解析清理失败，可再点「重试清理解析」。
5. 本监控可以：看阿里云域名、看 yyds 域名增减、往 yyds **添加**域名、从 yyds **删除**已绑定域名、在阿里云 **写/清冲突解析**、改本系统里的域名状态。
6. yyds 的 API Key、哪些域名给注册机用，由人自己配。本监控不改 API Key、不改 gptimage2api。
7. 第一次对账只对照、只监视，**不改任何已有解析**。
8. 解析只在「这条域名正被加进 yyds」时写。未使用排队期间不提前写 TXT/MX。

## 3. 账号与凭证

### 3.1 阿里云（多账号）

- 专用账号，里面全是接码域名。看见符合规则的新域名才进入未使用池。
- 必须支持 **多个阿里云账号**（调用风控高，多准备几把密钥，一个被限就换下一个）。
- 凭证：每个账号一对 `AccessKey ID + AccessKey Secret`。
- 权限必须同时有：
  - 域名：拉列表（`QueryDomainList` 一类）
  - 云解析 DNS：查/加/删解析（`DescribeDomainRecords` / `AddDomainRecord` / `DeleteDomainRecord` 等）
- 建议 RAM 子账号，不要用主账号万能密钥。
- **改某条域名的解析，必须打到拥有该域名的那个阿里云账号**，不能串号。
- 轮询要错开、单账号串行、失败退避。一个号被风控，跳过它继续用别的号。

### 3.2 yyds（多账号）

- 必须支持 **多个 yyds 账号**，名额不共用，各读各的实时套餐。
- 凭证：用户名/邮箱 + 密码。当前账号 **没有二验**。
- 登录走官方 API，不是网页点：
  - `POST https://maliapi.215.im/v1/auth/login`
  - 入参：`username`、`password`
  - 返回 `access_token`；并种 Cookie：`yyds_access_token`、`yyds_refresh_token`
- 加域名、验证解析、开泛解析必须用登录 JWT。`AC-` 开头的 API Key **不能**管 `/v1/me/domains*`、`/v1/me/wildcard-rules*`。
- 刷新：`POST /v1/auth/token/refresh`，读 refresh Cookie。每次刷新会轮转；旧 refresh 再用会把整家 token 吊销。所以 **每个 yyds 账号的刷新必须串行**，不能并发刷新。
- 公开状态曾确认：全站密码登录开启，Turnstile 关闭。若以后登录失败（改密、开验证码、开二验），面板上该账号标红，停止对该账号加域，不影响其它账号。

### 3.3 监控面板自己

- 一个登录密码，密钥加密存放。
- 没有面板登录的话不能直接挂公网。

## 4. 核心流程（必须按此执行）

```
阿里云多账号轮询域名列表
        │
        ├─ 首次（或新加的阿里云账号首次）拉到的域名 → 状态「已使用」，不写解析，不往 yyds 加
        └─ 之后新出现的域名 → 状态「未使用」
                │
yyds 多账号轮询域名列表与配额（主监测：域名是否增减）
                │
        有泛解析空位 且 有「未使用」域名
                │
        立刻：把选中的未使用域名加进对应 yyds 账号
                │
        立刻：按该账号返回的 dns-guide 在对应阿里云账号写 TXT + MX + 泛解析 MX
                │
        重试验证；成功则该域名「未使用」→「已使用」
```

触发补位的两种情况 **都要马上补**，不是二选一：

1. 某个开着「接收新域名」的 yyds 账号还有泛解析空位，并且库存里有未使用域名。
2. 监测到某个 yyds 账号的域名少了（人在本监控或 yyds 官网删除）。

「马上 / 第一时间」指：删减或空位一旦被扫到，立刻进入加域+写解析，不等下一轮很久以后的阿里云扫描。新域名出现本身仍靠阿里云列表轮询（无官方购买推送）。

## 5. 域名状态

只保留两档业务状态，外加异常：

| 状态 | 含义 | 谁会改 |
| --- | --- | --- |
| 未使用 | 可以往 yyds 加 | 新买默认；人可手动改 |
| 已使用 | 不自动往 yyds 加 | 首次对账默认；加进 yyds 成功后自动；人可手动改 |
| 异常 | 加失败、解析失败、未实名、NS 不是阿里云、yyds 返回 409 等 | 系统写入原因；人可改回未使用/已使用后重试 |

规则：

1. **第一次对账**（以及后来新加的阿里云账号，该账号第一次拉列表）：该范围里拉到的阿里云域名一律 **已使用**。包括「阿里云有、yyds 没有」的老域名。避免把旧域当新域补进去，也避免改已有解析。
2. **对账完成之后**，阿里云列表里新出现的域名默认 **未使用**。
3. 成功加进 yyds 后，自动变成 **已使用**。
4. 人在本监控或 yyds 官网删掉某域名后：这条域名在本系统里 **继续已使用、未绑定**，绝不能自动变回未使用。补位时从未使用里拿 **另一条**，不会把刚删的那条加回去。本监控删除时还会清掉对应邮箱解析。
5. 人可以在列表里手动改 未使用 / 已使用。想指定下一条就只把那条留成未使用。
6. 想让一条已删域名再被用：人手动改成未使用。系统不自动做这件事。

多个未使用时：按阿里云 **注册时间从早到晚**，先买的先补。不用「最新的优先」。

## 6. yyds 空位、满员、多账号分配

### 6.1 什么叫满

以 **泛解析名额** 为准，不是自定义域名总数。

现价只作对照，运行时必须读账号实时配额，禁止写死套餐表：

| 套餐 | 月费 | 自定义域名 | 泛子域名规则 |
| --- | --- | --- | --- |
| VIP | 0 | 88 | 5 |
| Plus | 9.9 | 188 | 5 |
| Max | 29.9 | 50 | 15 |
| Neo | 99.9 | 不限 | 999 |

说明：

- 定价页「N 条泛子域名」= `maxWildcardRules`（规则条数），不是预先创建 N 个子域。
- 一个域名只开 **1 条** `*.domain` 规则。注册时再随机出 `user@随机.domain.com`。
- VIP 88 个域名但只有 5 条泛解析。自动补位在泛解析用完后就视这个号为满，去填下一个号。
- Max 的域名上限比免费 VIP 还少，所以必须每次 `GET /me`、`GET /me/quota` 读当前值。
- 读到的有效上限若为 `-1`，视为不限。

### 6.2 每个 yyds 账号

- 页面上可开/关 **接收新域名**。关着的号：不自动往里加，仍监测其域名列表和配额。
- 账号顺序可配。多个号同时有空位时：按顺序，**填满第一个再填第二个**。
- 监测到某个号域名少了：优先补回 **那个号**（仍须该号开着接收，且泛解析还有空位）。
- 同一条域名同一时间只能进一个 yyds 账号，加之前要在本系统所有 yyds 账号的域名列表里查重。

### 6.3 加域时开泛解析

因为只有「还有泛解析空位」才会自动加，所以加的时候带 `enableWildcardRule: true`，并按 guide 写 `*.` 的 MX。

## 7. DNS / 解析（阿里云）

yyds 不是改 NS 到 yyds。NS 仍留阿里云。yyds 要的是记录：

- 验证 TXT：主机形如 `_yydsmail-verify.域名`，**值只有加进某个 yyds 账号之后才有**，不能提前写死。
- 根域 MX
- 开泛解析时再补 `*.域名` 的 MX
- 不需要 CNAME
- 记录内容以该次 `dns-guide` 为准，禁止写死 MX 主机名

接入当下（不是排队时）顺序：

1. `POST /v1/me/domains` `{ domain, enableWildcardRule: true }`
2. 取 `dns-guide`（或等价预览）
3. 在拥有该域名的阿里云账号上：
   - 若域名还没进云解析，先加入解析
   - 删掉会冲突的记录：停车页、`@` / `*` 的 CNAME，以及我们（或旧 yyds）写过的验证 TXT、MX、通配 MX
   - **不删 NS / SOA**
   - 按 guide 写入 TXT、MX、通配 MX（默认线路）
4. `POST /v1/me/domains/{id}/verify`，传播中要重试；不要一次失败就判死整条队列
5. 仍失败：该域名标异常并写原因，换下一条未使用（若还有空位）。人可稍后改状态重试

其它：

- 第一次对账绝对不改已有解析。
- 未实名、状态不正常、NS 不是阿里云：标异常，不硬改。
- 中文/IDN 用 punycode 对齐。
- 同一域名在 yyds 全局只能绑一个用户。若 409（仍绑在别人或本账号删除未完成）：标异常，不占死队列。
- 必须等「yyds 列表里已经看不到被删域名」再给该账号加新域，避免 409 和名额未腾出。

域名默认 **私有**，不要设成公开。

## 8. 监测什么、不监测什么

主监测：

- 每个 yyds 账号里的自定义域名列表增减
- 每个 yyds 账号实时套餐：泛解析已用/上限、域名已用/上限、接收开关
- 阿里云各账号域名列表（发现新买的、对上「这条解析该打哪个阿里云账号」）
- 未使用库存、进行中的加域/写解析、异常

第一屏必须一眼能看出：

- 排队未使用有多少
- 各 yyds 账号满不满（泛解析）
- 登录是否失败
- 阿里云是否风控/限流
- 最近一次补位/失败原因

不监测、不做：

- OpenAI 注册成败、是否拉黑
- 接码收信
- 整域清空阿里云解析
- 改 gptimage2api 配置
- 改 yyds API Key 域名范围

## 9. 面板功能（中文）

1. 登录（本系统密码）
2. 阿里云账号：增删改 AccessKey、启用/停用、风控状态、上次拉列表时间
3. yyds 账号：增删改账密、顺序、接收新域名开关、登录状态、实时配额、当前域名列表；从本监控移除账号不会删除 yyds 网站上的域名
4. 域名库存：阿里云列表 + 状态（未使用/已使用/异常）+ 归属哪个阿里云账号 + 是否已在某个 yyds 账号 + 注册时间；可手动改状态；已绑定且非补位中的域名可「从 yyds 删除」；解析清理失败时可「重试清理解析」
5. 立即扫描
6. 操作日志：发现新域、加 yyds、写解析、验证、扫到删减、从 yyds 删除、失败原因。禁止把密码、AccessKey、JWT、验证 TXT 值打进明文日志

## 12. 构建方案

### 12.1 技术选型

| 项 | 选择 | 原因 |
| --- | --- | --- |
| 语言 | Python 3.12 | 独立运维小端，阿里云官方 SDK 与 yyds JSON 都好接 |
| Web | FastAPI + 中文前端 | 每天要看列表、改状态、管账号 |
| 数据库 | PostgreSQL | 本机项目统一用 PG，不用 SQLite/MySQL |
| 运行 | Docker Compose：应用 + PostgreSQL | 必须一直开着，否则官网一删补不上 |
| 阿里云 | 官方 OpenAPI（域名 + 云解析 DNS） | AccessKey 签名 |
| yyds | `https://maliapi.215.im/v1` | 登录 JWT + Cookie 刷新 |
| 密钥 | 环境变量主密码加密后存库 | AccessKey、yyds 密码、refresh cookie 不进 git、不进明文日志 |

不依赖 gptimage2api 源码。作者身份按本机惯例：`biubiubiu125`。

### 12.2 建议目录

```
domainslot/
  docs/yyds邮箱域名监测-总方案.md   # 本文
  app/
    main.py                      # FastAPI 入口、鉴权
    config.py
    db/                          # PostgreSQL 模型与迁移
    crypto.py                    # 密钥加解密
    aliyun/
      domain.py                  # 域名列表
      dns.py                     # 读/删冲突/写 guide 记录
    yyds/
      auth.py                    # 登录、Cookie 刷新（每账号单飞）
      domains.py                 # 列表、添加、dns-guide、verify、配额
    worker/
      poll_aliyun.py             # 错开轮询各阿里云账号
      poll_yyds.py               # 较高频轮询各 yyds 域名增减与配额
      fill.py                    # 选未使用域、加 yyds、写解析、改状态
      locks.py                   # 同一域名、同一 yyds 账号互斥
    web/                         # 中文页面
  tests/
  Dockerfile
  docker-compose.yml
  .env.example
```

### 12.3 数据（PostgreSQL）

最低表：

1. `admin_auth`：面板密码哈希
2. `aliyun_accounts`：名称、加密 AccessKey、启用、上次成功/风控时间
3. `yyds_accounts`：名称、加密账密、加密 cookie/token、顺序、接收开关、上次登录/拉列表、缓存的配额
4. `domains`：
   - 规范化域名、punycode
   - 归属 `aliyun_account_id`
   - 注册时间
   - 状态：`unused` / `used` / `error`
   - 是否首次快照内（首次拉到的永不自动变 unused，除非人手改）
   - 当前绑定的 `yyds_account_id`（未绑为空）
   - yyds 侧 domain id（若有）
   - 异常原因、更新时间
5. `yyds_domain_snapshots`：每个 yyds 账号上一轮域名集合，用于发现删减
6. `jobs` / `event_logs`：补位任务与审计（脱敏）

唯一约束：同一规范化域名全局一行，防止两个 yyds 号抢同一域。

### 12.4 工作线程要点

- **yyds 列表轮询高于阿里云**（删减是主信号）。建议 yyds 约 15–30 秒；阿里云各账号错开，约 60 秒量级，被限流则指数退避。
- 发现 yyds 域名集合变少：确认少的是哪几条 → 本地对应行保持已使用、清空「当前绑定」→ 若该号接收开着且泛解析有空，立刻 `fill`。
- 发现阿里云新域（不在库里）：插入为未使用（该阿里云账号若还在首次快照阶段则插入为已使用）。
- `fill` 单线程/每 yyds 账号一把锁：选最早注册的 unused → 加 yyds → 写 DNS → 重试验证 → 改 used。
- 验证 `dns_propagating` / TXT、MX 暂缺：有限次退避重试后再标 error。
- 未使用为空但 yyds 有空位：第一屏提示「有空位但没有未使用域名」，新域一出现再补。
- 所有号满且有未使用：第一屏提示「有未使用但 yyds 已满」，等人在本监控或官网删。

### 12.5 yyds 接口（实现时以 OpenAPI 为准）

基址：`https://maliapi.215.im/v1`

| 用途 | 方法 |
| --- | --- |
| 登录 | `POST /auth/login` |
| 刷新 | `POST /auth/token/refresh` |
| 资料与配额 | `GET /me`、`GET /me/quota` |
| 套餐表（仅展示，不以表代替实时配额） | `GET /plans` |
| 我的域名 | `GET /me/domains`、`POST /me/domains`、`DELETE /me/domains/{id}` |
| 解析说明/状态/验证 | `GET /me/domains/{id}/dns-guide`、`dns-status`、`POST .../verify` |
| 泛解析规则 | `POST /me/domains/{id}/wildcard-rules` 等 |

添加域名成功前没有 TXT 值。`enableWildcardRule` 可在创建时打开。

### 12.6 阿里云接口（实现时以官方文档为准）

- 域名列表：Domain `QueryDomainList`（分页、注册时间、状态）
- 云解析：是否已添加、未添加则 `AddDomain`；`DescribeDomainRecords`；删冲突；按 guide 添加
- 线路：默认
- TTL：用控制台允许的最小值或 600
- 被限流：记到该阿里云账号，换号，退避

### 12.7 安全与运行

- `.env`：面板密码、库连接、加密主密钥、监听地址
- Docker 只暴露必要端口；默认建议本机或内网
- 中文 UI、UTF-8
- 时区：`Asia/Shanghai`
- 健康检查：库通、worker 活着、各账号上次成功轮询
- 测试在 WSL 跑 pytest；不把真实密钥写进测试
- 以后若上传 GitHub：作者仅 `biubiubiu125`，并配 GHCR 自动构建。当前先本地独立运行

### 12.8 验收（做完必须对上）

1. 首次接入已有阿里云/yyds：只对账，解析一条都不变；已有阿里云域名都是已使用。
2. 之后阿里云新买域名：自动未使用；若某 yyds 号有泛解析空位，马上加并写解析。
3. 人在本监控或 yyds 官网删一条：监控马上从未使用补另一条；被删的那条仍是已使用、未绑定。本监控删除还会清对应邮箱解析。
4. 泛解析满的号不再自动加；开着接收的下一个号继续加。
5. 关掉某号「接收新域名」后不再往该号加。
6. 已绑定且非补位中的域名，库存表有「从 yyds 删除」；解析清理失败时可「重试清理解析」。
7. 多阿里云号：解析打到域名所属账号；一号限流不影响其它号。
8. 手动把某条已使用改成未使用后，有空位会补它（按注册时间排队）。
9. 监控进程停掉期间官网删的域，启动后对账仍能发现并补上。

## 13. 一句话总流程

**多阿里云提供域名库存（新的未使用、老的已使用），多 yyds 按泛解析空位自动加域；人可在本监控或 yyds 官网删废域名（本监控删除会清对应邮箱解析）；监控发现空位或删减就立刻从未使用里补，并在补的这一刻写阿里云邮件解析。**
